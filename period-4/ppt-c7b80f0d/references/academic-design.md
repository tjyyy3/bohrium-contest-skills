# Academic slide design

Use the actual audience, time, slide count, template and editable-object rules from `case.json` and the task. These layout choices apply when the case permits them.

## Set the story before the layout

Give each page a distinct job. For a short research talk, open with a concrete question, establish how the comparison was made, show the strongest evidence, and close with what it supports and which questions remain. Compress setup to give the audience time to read the evidence. Omit general background when the audience already knows it. Include literature only when the source and case support it and it helps explain the specific gap.

Write the slide titles in order and read them by themselves. A results title should name the finding, comparator and condition when that condition matters. A setup title can simply name the design or population. If a claim needs a qualifier to be true, keep it in the title or directly beside the supporting evidence. Mark hypotheses explicitly. Use the time budget to decide which details belong in speaker notes. Notes should tell the speaker where to point, what the visual establishes and how to transition. A numerical title needs its own source locator.

## Let the evidence determine the page

| Audience task | Visual | Verify before delivery |
|---|---|---|
| See what was varied and held fixed | Editable condition matrix or a schematic based on the documented workflow | Factors, units, reference conditions, specimen counts and independent versus technical repeats |
| Compare magnitudes | Grouped columns from zero, or a labeled dot plot with an explicit axis when accurate differences matter | Series names, order, baseline, axis limits, exact source numbers, uncertainty type and sample size |
| Look up exact values across conditions | Native table with aligned numbers and units in headers | Original precision, denominator, per-condition `n`, relevant exclusions and reference group |
| Read a source figure, image or equation | An attributed source panel at native aspect ratio, or an exact editable reproduction when required and feasible | Panel identity, scale, legend, annotation, symbols and definition of the measured quantity |
| Judge what follows from the findings | Aligned rows connecting the observed result, the warranted inference and the additional evidence needed | Limitations from the source and clear labeling of any presenter-proposed test |

Use one primary evidence view per slide when possible. Group annotations and captions with their evidence. If a paper figure is too dense for projection, show a relevant panel and retain the necessary axes, scale, legend, conditions and citation. Give a source panel a full-width page when its labels would otherwise be unreadable. Avoid duplicating a figure as a paragraph or inserting a generic picture in its place.

Use an editable chart when the actual numbers are available and the case permits a redraw. Store the numbers in the chart's data object or embedded workbook. Use chart-native labels for values that should update with the data. When an editor fails to preserve a chart or embedded workbook, try another available compatible editor or report the remaining limitation. Inspect both the data and the render. Use an editable table if exact lookup communicates the evidence more directly than a chart.

## Apply a consistent hierarchy

Keep the case's title, footer, logo and typography rules. Use consistent margins and align the title, evidence and source on a shared grid. Let the main visual occupy most of the available space. Use size and weight to distinguish the claim, evidence labels and source credit. Put a compact source locator beside the visual or in the footer and the complete locator in the notes and evidence map.

When a new 16:9 design is allowed, start with about 5% horizontal margins, a light neutral background and dark text. On a 13⅓ × 7½ inch canvas, start with 32–42 pt slide titles, 20–26 pt main text, and 16–20 pt figure labels. Allow smaller source credits only where they stay legible. Adjust by the canvas and projection context. Prefer installed fonts that cover the input language and scientific symbols. Test the actual glyphs for superscripts, degree signs, Greek letters and minus signs. Reserve color for meaning. Encode conditions consistently across pages and pair the colors with labels or marker differences. Cut text or change the layout before reducing type to fit.

## Materials-science profile

- Identify the actual material, composition or fabrication route, the controlled conditions and the measured property. Treat pressure, temperature, thickness, area and loading as distinct quantities. Copy the property name and units from the source. Do not rename pressure-normalized permeability as flux or equate a microscopy signal with a directly measured mechanism.
- Show sample preparation, characterization and measured outcomes only at the granularity documented. A method schematic can expose experimental logic but must be labeled as a schematic. If controls or replication are unclear, say so in the ledger and at the point of interpretation.
- Compare methods within equivalent test conditions where the source supports it. Preserve whether values are per specimen, averages, distributions or fitted estimates. For a relative contrast, state its reference group and retain the source values and formula. Use reported uncertainty and label what it represents. Means alone cannot yield error bars, effect significance or mechanism.
- Distinguish observed performance from a proposed mechanism or practical recommendation. If selectivity, degradation, scalability or another outcome is unmeasured, limit the inference to the properties tested. Include a follow-up only where the source or the talk's discussion scope supports one.

After export, inspect the full sequence and then each page at reading size. Check whether the comparison can be understood from the chart and its labels alone, whether the conditions and scope are visible, and whether the notes fill in context without repeating the slide. Record revisions and the final renderer and fonts. See [sources and licenses](upstream-attribution.md) for the design methods adapted here.
