# 引用与事实核验 · v1.0

当用户提交科研材料、原文和检查项，需要判断引文是否支持论断、数字或来源是否可靠时调用。按用户语言写报告，短摘保留原语言。接受 PDF、扫描件、纯文本、摘要、补充材料、表格和数据字典。Agent 负责读文和判断；随附 anchor.py 是本地证据复核器，不能判断语义。

## 开案与中断恢复

1. 读 /input/case.json、实际 task.md 和环境列出的 resources.yaml，列出实际文件。以原文的题名、章节、图表和实际内容识别学科与材料。逐字保留 case_id，抄录 output_contract 的每个字段、类型、嵌套结构、枚举、语言和必需文件。若为描述式合同，逐项列清交付键。需求中的特定 facet 和 finding type 优先于下文默认词表。
2. 建 /app/work 和 /app/output。在 work 建 coverage.tsv，每行一个「具体检查项 × 有关章节」，含所需证据、定位、状态及已审 claim ID。六个方向均留记录（见下）。先把合法的部分 result.json 写进 output，保留合同字段；使用合同允许的空数组、状态和未完成原因。写到同目录临时文件再替换；只在状态确有变化时更新。过程中以来源为单位缓存和继续，中断后先读 coverage 和已完成条目，再处理剩项。
3. 优先核对影响核心结论的数值、反向语义、重大版本变化和被多次使用的引文，再扫摘要、方法、结果、图表及讨论。900 秒、64 次模型请求是单次上限。预留时间产出结果，受限时逐项交代未检查内容。

## 两端定位

- 为每个文件分配来源编号。记录实际取得的路径或 URL、标题、作者、日期/版本、来源类型、全文/摘要/仅书目等权限。相同来源的不同版本各给编号。第一手测量、原始数据、综述转述和元数据，能证明的事项不同。URL 可访问性、更正、撤稿和最终发表状态须有相应记录；未查询写「未查」，查询无结果只陈述检索范围、日期和结果。
- 优先读取原附件。可运行下述工具缓存按页文本和原件 SHA-256。对双栏错序、图注、上下标、负号、±、脚注和表格行列回看原页。扫描件若可用则逐页渲染、OCR 再肉眼核对；记录页码、区域和 OCR 的不确定字符。无提取能力或权限时保留可查页，区分工具错误与文件缺失。禁止由文件名、模型记忆、搜索摘要生成原文或页码。
- 稿件端定位用「文件/版、PDF 物理页（1 起算）及印刷页若可见、章节/段首/图表编号、短摘」。来源端独立定位；表格要列名、行名、单位与注释，图要面板、轴、图例。暂时找不到独立来源即保留此缺口。一篇稿件自身可验证内部一致性，不能充当自己的独立外部佐证。
- 在许可范围内按 DOI 或精确题名检索，核对标题、作者、年份、期刊/版本。记录实际采用的元数据来源和检索范围。一个 DOI 可识别作品，不能直接证明方法或结果。多个候选同名、场合或版本相近时保留候选及区分字段，来源不可判定前勿选一个作结论。优先检查引文所指版本，相关正式版/更正若可得再并排定位，明确引文版本与当前有效版本分别支持什么。

## 逐条判定

1. 划出原句所用引文标记，把并列谓词、多组数字、比较、机制、推广范围拆成原子论断。保留句法上引文所指范围。一个论断多篇引文时逐篇核对并说明合并后覆盖的部分；一个引文支持前半句并不自动支持后半句。无引文的可核事实也登记。
2. 分两列判定。**书目身份**取匹配、冲突、歧义、未取到、无引文。**语义支持**取完整、部分、不支持、无法判定。用材料/人群、条件、测量与单位、参照组、方向与数值、时间、统计不确定度、措辞强度对齐。等价单位换算写算式并保留原值。直接确证全部要素才判完整。部分支持须写「已支持什么、仍欠什么」。实质相反或实际检查的范围明确不能支持该命题时判不支持，分别标明反证或无关；只有原文明确排除或直接冲突才写事实错误。摘要遗漏细节、全文取不到、歧义或尚未完成检索判无法判定。全文未搜到某词也不能独立定反证。
3. 做双向检验：把论断与证据各改述为一句可证伪命题，先找最强支持，再查相反解释（不同温度、样本、度量、因果与关联、模型与实验）。摘录应足够看清限定词。跨文体比较区分作者自己的结果、其对前人工作的转述和作者推测。
4. 覆盖六类检查，按本案实际要求细化。事实核验比对量值、适用范围与版本；引用支持核对上面两列；方法设计查结论所需的对照、独立样本和测量条件有无交代；统计报告核对 n 的单位、误差定义、效应、区间和图表；论证链追踪描述→比较→因果或外推所增加的假设；学术规范核对实际被要求的归属、数据可用性、版本声明等。缺少声明写清是「所给材料未见」还是「原文明示没有」。某项确实不适用或未检查须列原因。禁止按类别配额凑问题。
5. 为同一根因合并重复发现，保留所有受影响位置。问题类型分别写事实错误、证据不足、规范问题或建议；通过项亦有可回查的证据。状态默认通过、问题、待复核、未检查，映射至实际合同。严重度由纠正后的科学影响决定：高＝主要效应方向、关键数值、主要证据链或核心结论须改变；中＝重要子结论、适用范围或复现受影响；低＝可定位的次要表述/规范问题。通过项写不适用。待复核独列潜在影响和验证优先级，绝不把高优先级写成已确认的高危错误。
6. 每项给最小可执行修改及复验条件，例如收窄到明确测过的温度区间、写明每个样品的重复次数、请作者提供指定版本的表格。替换文献、数值、单位只有确有证据才给。部分支持给一条保留已证实部分的具体改写。

## 交付与检查

严格按本案合同写 /app/output/result.json 及指定文件。合同细节以真实输入为准。条目至少能读出：编号、检查项与问题类型、原句位置/短摘、原子论断、书目身份和支持程度、来源编号/版本/位置/摘录、判定理由（含适用边界）、状态、严重度及影响、修改建议和仍需的证据。指定结构没有容纳字段时，将细节放入合同允许的证据或报告附件，不修改受限枚举或正式 schema。汇总通过、问题、待复核、未检查项；另列材料缺失、判断不确定、未执行、运行错误，分别写恢复方式。覆盖表、来源表、版本与变更记录按合同保留。记录实际操作；正式分数和对照由平台生成。

检查所有引用标记和检查项在覆盖表有去向；结果与表中计数一致；中高严重度至少一次回读原页与来源；通过项也复读限定条件。保留原始结果、操作日志、复核表与本次修订记录，放入约定位置或 work。用 json.tool 验证 JSON，并逐项对照真实 output_contract；有 JSON Schema 和相应校验器则执行校验。以下工具检查文字定位，不能代替上述合同与语义检查。

## 本地调用示例（虚构材料，示意）

文本路径仅需 Python 3.9+ 标准库；PDF 路径优先使用环境中的 pdftotext，可执行文件不存在时自动尝试已安装的 PyMuPDF（fitz）；两者都缺失时执行人工定位流程。anchor.py 与本文件同目录，无需安装。路径按运行环境调整。可先运行 python /skills/weekly-skill/anchor.py --help。

示例稿件 draft.txt 内容为 “The film expanded at 310 K.”，实测记录 record.txt 为 “At 310 K the film expanded along the normal.”。实际输入有 PDF 时直接用该 PDF 替换文本路径。以所在页为单位，在 work 执行：

```sh
python /skills/weekly-skill/anchor.py index index.json draft=draft.txt lab=record.txt
python /skills/weekly-skill/anchor.py find index.json lab "At 310 K"
python /skills/weekly-skill/anchor.py check index.json anchors.json
```

anchors.json 是由 Agent 依据实际阅读写成的数组，每条格式为 {"id":"C1.source","doc":"lab","page":1,"quote":"At 310 K the film expanded along the normal."}。同时登记 C1.manuscript 的实际摘录。check 会给出是否唯一、片段位置与原件哈希，并在核验失败时返回非零。无法访问、仅图像或非文字证据须另记原页区域和目视复核结果，切勿制造文字锚以换取通过。

示意结果：C1，稿件第 1 页原句如上；来源 lab，第 1 页证实法向膨胀。若原句指法向，支持完整；若上下文要求各向同性，法向实测仅支持一部分。需回查稿件的方向定义；来源为给定实验记录，无书目引用。实际案例均须从零阅读和独立判断。
