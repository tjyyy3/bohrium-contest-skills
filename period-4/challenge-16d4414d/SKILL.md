# 论文逻辑与论证审查

把一篇稿件审成一份作者能逐条修改、评审能回原文复查的报告。使用输入要求的语言，证据引句保留原文。结论来自稿件及实际提供的附件。适用于实验、观测、建模、综述和理论工作。检查统计表述、规范和引用时，聚焦它们对论证的影响。无需重做原始数据分析、润色全文或判断学术不端。

## 1. 先确认要交什么、可读到什么

读取 /input/case.json、同案 task.md 和实际材料。逐项记录原始 case_id、output_contract 的键名/层级/类型、指定文件名、该案点名的 review facets、分类枚举、所需证据及修订格式。原样使用这些约定；若额外字段受限，把本流程的附表放入指定报告。输入标签和文件名不能证明研究内容。无固定接口时也可给一篇稿、审查范围和报告目录，默认生成 result.json 和 review.md。

在 /app/work 记录一张阅读表，每行列文件名/版本、正文或附件、页段/小节、解析情况、读过的范围、待查项。区分 PDF 物理页和印刷页码。文本/Markdown 按标题、段、唯一引句定位；JSON 内嵌文章按字段路径定位，数组保留原下标。PDF 可运行 `pdftotext -layout paper.pdf /app/work/paper.txt`，保留分页符。遇到双栏串行、负号或上下标丢失、图表正文空白，渲染相关页并查看图例、脚注、单位。扫描件在可用时分页面 OCR 并与页面对照。OCR 未确认的字使用图中位置描述，避免作为逐字引文。对每个打不开的附件分别记录原因和影响。

长稿先列目录、各节首尾、图表与附录索引。优先阅读全文中的主张所在段、相关设计/结果以及限制段；再分段补齐余下检查项。每段留首尾位置和已查对象，跨段接续同一主张 ID。搜索命中只作索引，孤句前后的定义、转折、条件、归属必须读。先存可解析的部分结果到 /app/output；预算趋紧时优先闭合主结论证据链，并列出未读范围。

## 2. 建立主张与证据的对应表

按该案重点选取标题/摘要的决定性结论、引言承诺、结果/讨论的支撑与限制。保留有支撑的主张，以便区分失配与正常对照。每行可以简写为：

|ID / 主张引句及定位|主体与强度|支撑前提、来源定位|连接前提与结论的必要条件|当前结论及理由|
|---|---|---|---|---|
|C…|作者实测、作者推论、他人观点、假设、预期或否定；适用条件|本文数据、方法、图表、推导、引用原文或作者转述|比较对象、测量量/代理指标、设计、边界条件及替代解释|充分、部分支持、抵触或无法判断|

从主张向后追方法和证据，再从结果向前追它回答了哪个问题。做两次对齐：

- **同口径**。把研究对象、样本/独立单位、比较基线、条件、时标、量纲、方向、精度、显著性与适用范围并排。数值不同时先检查不同分组、不同定义、误差口径、单位换算、模型输出和实测值。理论稿检验命题的前提是否在应用时满足，数值模拟稿核对边界条件与推广目标，综述稿区分作者综合结论和被引研究的样本范围。
- **同强度**。列出最弱、仍足以解释现有证据的结论，再看原文是否跨到更强断言。如两组同时改变了两个条件，证据可支持联合条件下的差异，分离单因素效应需要额外比较。引用条目只能证明作者引用了该文；要断言引文不支持主张，须读到所引来源的有关文字。只有摘要时限定核对范围；获取不到时记录待复核的文献和所需段落。

沿引言承诺→方法定义→结果/图表→讨论限制→摘要结论来回核对。出现不一致时记录两个端点的原句/图表位置和各自的实际含义。要报告“未交付”，先查同义术语、图注、补充材料及改用的指标，在阅读表中写出查过哪里。无法访问的附录可能容纳该结果时，把结论限定为“在所读范围未定位到”，标记待复核。

## 3. 决定是否成案

对每个疑点依次问：这是谁的断言？属于哪个实验条件和时间点？全文有没有明确限定或反证？一句话能否同时容纳两个说法？有主文特指、假设推演、引用归属、正常对照或单位换算能消解疑点时，记录为有依据的通过项。真实矛盾应展示同一口径下不能同时为真的两个陈述。证据缺口写明缺的桥梁以及可能改变判断的材料。不可拿缺证据当作反面事实。

按案件给定类别命名；如未指定，用“事实错误/内部矛盾”“证据不足/推理跳跃”“规范或报告问题”“建议性意见”，另记状态“通过/问题/待复核/未检查”。建议与已证实的错误分别计数。对核心论点逐项交代事实、引文支持、方法设计、统计报告、论证链、学术规范六类检查及本案额外 facet。事实检查核对同口径叙述，方法检查设计能否回答问题，统计检查作者的量和比较是否对应，规范检查归因、定义和限制是否透明。对不适用项解释理由；扫描缺页、未给引文和预算内未读是不同原因。不要为了填满各类而创造问题。

按影响排优先级。**高**表示主结论或核心识别条件失去支持，即使修辞容易修改也可能属高。**中**表示一个次结论、比较或解释需要改动，主结果仍成立。**低**表示局部可追溯性或表达精度可以修正，且不改变结论。待复核可注明潜在影响，避免和已确认严重度混排。置信度与严重度分开：指出判断依赖的已读证据和仍缺的材料。多个段落沿用同一错误时列一条根因并附传播位置；不同修复才能解决的问题应拆开。

## 4. 交付作者可执行的修订

每条发现写出“位置与短引句 → 对照证据及位置 → 哪一步不成立、影响哪个结论 → 最小可行修订”。可给可直接替换的句子，保留单位、条件和方向；新增证据是另一条可选择的补救途径，写明需要何种比较才能维持原断言。不要虚构新实验结果。需要作者澄清时写一个能改变判断的具体问题。用一个验收条件说明如何确认修订完成，如摘要和讨论均已改为观察到的比较范围。

写入 /app/output/result.json 和该案要求的其他文件。每个必需原字段都用真实结果赋值。若无强制 schema，可用 case_id、status、main_result（主结论是否成立及范围）、claims、findings、coverage、sources、uncertainty、changes。发现含 id、claim_id、facet、type、status、severity、位置/引句、对照证据、判断依据、建议及验收条件。coverage 按 facet 指向证据 ID 或列原因；sources 标版本和实际读取范围；changes 记录本轮交付/修订和对应结果。区分运行状态和论文判定：审查完整可以发现严重问题；资料缺失/证据不确定可以留下有效局部结果；解析或程序失败单记 error 与恢复记录。同一证据的报告和 JSON 取同一份条目，避免数字和优先级漂移。

交付前，用原文逐条回查引句（表格核单元格、坐标轴核测量定义），确认每条建议只使用来源给出的事实，确认所有指定 facet 和合同键均已出现。独立复核者应能凭给出的文件、页/段或行号、引句一次找到原文并看懂相邻语境。多个相同引句必须带位置。

## 附带工具与最小调用

版本 1.0。本目录的原创 evidence.py 使用 Python 3 标准库，可直接运行；无需安装服务。它对可读 UTF-8 文本生成逐页行号，并检查指定行段是否含引句（仅折叠空白）。行号指所选阅读副本；在报告中注明原文件、版本和读者可用的段落/图表定位。视觉证据手动回查。工具不判断语义、引文归属或严重度。

以下是**虚构示例**。假设 /input/note.txt 仅有两行，分别是 `We tested one quartz tile at 290 K.` 和 `The result applies at all temperatures.`。调用：“按 manuscript-argument-review 审查 note.txt 的适用范围，写 result.json”。Agent 读取全文，执行：

```sh
python /skills/weekly-skill/evidence.py index /input/note.txt > /app/work/note.lines
```

拟定范围问题后，将如下一组引用（JSON 数组）写到 /app/work/quotes.json：

```json
[{"id":"C1","page":1,"first":2,"last":2,"quote":"applies at all temperatures"},{"id":"E1","page":1,"first":1,"last":1,"quote":"one quartz tile at 290 K"}]
```

运行 `python /skills/weekly-skill/evidence.py check /input/note.txt /app/work/quotes.json`。退出码 0 表示每条引句原位命中，1 表示至少一处不符，2 表示输入/解析错误。回到原文纠正或声明无法验证。示意审查结果：C1 是作者主张，E1 支持单一条件；若这是主结论，范围外推列高严重度证据不足。把第二句改为 “This result was observed for the tested quartz tile at 290 K.”，并核对摘要是否也注明条件。其余未提供的章节注明不可检查。本例仅演示流程；每次运行须读取本案材料重新判定。
