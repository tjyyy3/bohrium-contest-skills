# 从科研资料查到可复核的答案

**完成条件**　逐项回应工单中的每个问题、搜索与操作。每项事实结论都有读者能打开的来源版本、原文位置和短引文。记录检索范围、用过的查询、别名、限制与实际变更。允许得出“当前资料不足”。

## 1　识别工单与证据范围

读取 `/input/case.json`、当前 `task.md` 和工单引用的允许读取的控制文件。记录真实 `case_id`，提取全部 `output_contract` 字段、类型、列名、交付文件名、问题 ID、允许操作及禁止披露的资料。控制清单、元数据、行政备注、研究正文和已有索引各是什么，依据工单及文件内容确定。工单或题面不是研究论断的出处。在 `/app/work` 工作，先在 `/app/output/result.json` 保存符合原合同字段的部分结果，注明待核对项目，再逐项更新。以案例的实际路径、语言和交付约定为准。

用目录项先确认哪些路径可读、可索引、可向提问者引用。遇到按角色、记录或列设定的权限，先执行限制；工具的目录过滤只能处理整条路径。混合权限表先用工单许可的视图/字段导出到工作区，保留回指原记录的关系；无法保证隔离时把原件列为受限。工单只允许列名时，不读正文，不算哈希，不把被排除的标题、路径或引文泄露给无权读者。

## 2　建立索引与版本目录

附带的 `kb.py` 是本技能原创的离线命令行工具（索引格式 1），路径相对本文件。需要 Python 3.9 或更新版本；基础文本、HTML、DOCX 正文和 XLSX 单元格只用标准库。PDF 使用环境中的 Poppler `pdftotext`，不存在时用已安装的 `pypdf` 或 `PyPDF2`。先查 `environment/resources.yaml` 与实际命令是否可用。

```sh
K=/skills/weekly-skill/kb.py
W=/app/work
O=/app/output
mkdir -p "$W" "$O"
# LIB 设为案例中实际资料根。scope.json 由本次工单的授权范围生成。
python3 "$K" index "$LIB" "$W/index.json" --scope "$W/scope.json"
python3 "$K" search "$W/index.json" "检索词 表述变体" --limit 16 --out "$W/search-01.json"
```

`scope.json` 例为 `{"allow":["papers","register.csv"],"deny":["papers/private"]}`，路径均相对 LIB、使用正斜杠，子目录继承、拒绝优先。空的 allow 代表不读任何文件。仅在整个资料根确实都可读时才省略 scope。资料根不包含工作目录或输出目录。若材料直接嵌在 JSON 中，索引获准的 JSON 文件并以 JSON Pointer 定位。混合了题目、示例和材料的 JSON 应按许可提取材料部分，保留原指针映射。

索引包含目录层级、原始相对路径、扩展名、观察到的文件模式、实际读取结果、字节数、完整 SHA-256、重复字节指向、提取器状态和原文块。 `chunks[files[i].chunk_key].blocks` 是有序的［位置，空白规范化文本］。相同哈希合并检索，同内容但不同格式后缀分别解析。目录别名、软链接和符号链接可记录其存在，工具不沿链接扩展授权范围。保存原文件，除非工单授权，所有组织与恢复均在单独输出树进行。

按指定格式导出可交接的目录或索引；没有指定时可从 `files`、`directories`、`notices` 生成目录清单并另附实际搜索记录。对每项登记文件或缺失项补上工单要求的资料 ID、题名、作者、年份、DOI、来源、角色、许可、版本标签及其各自来源。用注册表的明确 ID、路径、标识符与文件内证据对齐；题名相似只作候选。原值、规范化值和依据分列；未知字段标为未知。既查“登记但找不到”，也查“实际存在但未登记”。不得从文件名臆造作者、版本或修订内容。控制文件和资料之间可通过外键以及多对多路径映射联系。

**版本决策**　同 SHA-256 证明两个路径指向相同字节，一件证据只计一次。相同逻辑资料 ID、DOI 或题名而哈希不同，应回查登记表、版本备注、正文及两个相关段落。记录 `from → to`、关系（字节副本/行政重命名/本地工作修订/有明文依据的出版修订/待判）、比较坐标、差异和依据。权限、来源与规范别名仍附着在各路径上。“当前版”只在工单或来源明确规定时成立。日期、mtime、“final”或排在前面的副本不足以裁定。行政备注能证明管理动作，科学结果须另引研究正文。

## 3　检索、作答、查缺

1. 逐题保留原文和 ID，拆出实体、关系、版本/时间限定、指标和单位。先搜确切标识、专名/缩写和少见术语，再用实际资料里发现的同义表述、中英文别名、旧名称、单位变体回查。机器按英文标记及汉字二元组作词项召回，按块内匹配和逆频率排序；匹配是线索，不表示支持。必要时用 `--path 子目录或文件` 聚焦来源，保留一次全授权范围的反证或旧版检索。针对表格先定位表头或行标，再读同一行、单位与脚注。对通用词命中过多时拆成短查询，检查不同文件，不要仅取第一条。
2. 在原文上下文核对范围、否定、引述他人、比较对象、数量、分母、单位与条件。保存每次查询文本、过滤范围、命中数、采纳与排除的记录及原因。每一条**可单独判断真假的论断**分配 claim ID，绑定一个或多个引文。结论来自计算时同时给输入值和定位、计算式及单位。跨文件合成要显示各来源分别支撑哪一部分，问题包含多个子问时分别给状态。
3. 引文结构为 `{"claim_id":"…","path":"相对源路径","sha256":"完整源哈希","locator":"索引位置","quote":"该处短原文"}`。复制 search 命中块中的短句，并读前后块。search 的长块只显示 900 字，完整块保存在索引。文本引用物理行；JSON 使用原指针；CSV/TSV 使用逻辑记录和列（含表头行）；DOCX 使用正文节点或表格行列段；XLSX 使用工作表名和坐标；PDF 使用从 1 开始的物理页和页内文本块，另记印刷页码如可见。一个引用只指一个位置，跨位置原文拆开引。同一文件多个目录别名优先采用工单指定的规范路径并复核该路径哈希。
4. 状态分为有直接证据、部分有据、来源冲突、在可读范围未找到、来源缺失、无权读取、解析失败。冲突并列双方原文、版本与条件，若可由明确时间/条件解释则说明适用面。未找到时列出查过的目录、词及未覆盖项，说明需要哪一种资料或字段；零命中不能证明科学结论为假。发现可能矛盾时再检索反向词或历史版本。置信说明用可观察的理由（如独立来源数、版本适用性和数据直接性），勿用无校准的百分比。
5. 将实际引用放入工作区 UTF-8 JSON 数组，执行 `python3 "$K" verify "$LIB" "$W/index.json" "$W/citations.json" --out "$W/verification.json"`。工具重读源字节、对照哈希并重新提取指定位置，要求短引文与该处文本在空白规范化后连续匹配。任何失败返回非零。这个检查不判读语义；逐条人工式核对“引文能否推出整个句子”，尤其检查否定、结果强弱和因果归因。多个来源可分别复核，最终检查每项已回答的事实都有支撑；零引文的非空事实答案须退回修改。

## 4　执行工单操作与交接

若只要求问答，交付可查的索引、答案和操作记录即可。若要求恢复别名、补齐资料副本或重建索引，落实到真实文件。先按工单列受影响 ID、源路径、目标路径、已核版本完整 SHA-256 和理由；一个字节流可能对应多个逻辑条目，按工单保留其关联。需要复制时，生成 plan 数组，每项含 `source`（相对 LIB）、`target`（相对指定交付树）、`sha256`、`reason`：

```sh
python3 "$K" restore "$LIB" "$W/index.json" "$W/plan.json" "$O/recovered" --out "$W/changes.json"
python3 "$K" index "$O/recovered" "$W/recovered-index.json"
```

工具比对源/目标字节；同内容重跑记为 already_present，目标异内容记为 failed、保留现物。核对目标数量及哈希，再用重建的索引重演相关搜索。要求修复元数据时，另写实际更正的清单/导出并回读验证主键、行数、外键与差异；若要求操作原生数据库或服务，依工单和已授予能力实际执行并验证，记录不可用的依赖。无真实数据库/账号不能宣称已同步。

将实际交付路径填入合同的原字段；除 `case_id`、主结果和每问状态，确保可交接资料覆盖目录清单、版本关系、来源锚点、权限及操作差异、异常和恢复。没有约定内层结构时可使用 `questions[]`（含问题、答案、claims、证据、状态与缺口）、`catalog`、`relations`、`search_log`、`operations`、`unresolved`、`artifacts`。保留所有原合同字段及其类型。重新打开最终 JSON 和每个附件；将对外清单/搜索记录中的受限内容按权限遮盖，原文索引只有在工单允许交接全文时才随附件输出。直接从输出的引用回到原文件复读；只写计划的操作保持待办状态。

## 最小调用示例（自拟，示意）

令 `LIB=/app/work/demo-sources`，目录下唯一的 `lamp.txt` 第 1 行为 `The lamp was measured at 8 lux.`。示例问题是“测得的照度是多少？”

```sh
python3 "$K" index "$LIB" "$W/demo-index.json"
python3 "$K" search "$W/demo-index.json" "lamp lux" --out "$W/demo-search.json"
python3 -c 'import json,sys; h=json.load(open(sys.argv[1]))["hits"][0]; print(json.dumps([dict(claim_id="C1",path=h["path"],sha256=h["sha256"],locator=h["locator"],quote="8 lux")]))' "$W/demo-search.json" > "$W/demo-citations.json"
python3 "$K" verify "$LIB" "$W/demo-index.json" "$W/demo-citations.json"
```

示意回答是“该记录测得 8 lux〔C1，lamp.txt，第 1 行；完整哈希见引用清单〕”。若另问光源型号，该单行未提供型号；记录按型号、制造商等检索的范围，并指出需要设备登记或方法段。复用时根据实际用语编写查询，切勿把例子的结论带入案例。

## 已知边界与维护

目录为空时报告零个资料文件；对照登记项标出待补材料。排除项、跳过链接、权限拒绝、目录枚举失败、损坏格式、无文本与提取不完整分别保留。文本支持 UTF-8 与带 BOM 的 UTF-16；其他编码经确认后制作工作副本并保存映射。DOCX 的页眉、脚注、批注和浮动对象，以及 XLSX 的格式化日期、图表和外链需用相应原生查看器核对。PDF 空白页/扫描图像、双栏错序、图表及数学符号应按页渲染查看，允许时 OCR 并记录工具、页码、截图/坐标与人工核对；OCR 引文单独按页复核，不伪装为通过文本验证。缺少解析器时仍保留哈希和故障原因，换用已有合规工具或标记未覆盖。移动、更新或重新解析资料后重建索引并重查受影响的回答。索引为内存内 JSON，超大库按批准的目录分片并跨片检索。
