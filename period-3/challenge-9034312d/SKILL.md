# Draw a source-bound technical route

Use this Skill for a small technical route with steps, branches, merges, detection and return loops. Treat an apparatus layout as a schematic only when supplied component and interface descriptions support it. Do not infer physical pipes, mechanisms or control links from mere chronology.

## Read the actual case

Read `/input/case.json`, the actual `task.md`, all referenced materials and `environment/resources.yaml` when present. Use the case's requested names, language, dimensions, output schema and editable format. Work in `/app/work`; save actual outputs in `/app/output`. Local trials may use explicit alternative roots. Never infer source contents from a filename or topic label.

Write an early `result.json` with `case_id`, every original `output_contract` field, an honest incomplete status and missing inputs. Then replace incomplete fields as work succeeds. Preserve fields even if they do not fit this Skill's usual outputs. Missing material, uncertain interpretation and export failure are different conditions. A missing source is not permission to invent a protocol. Keep model and run metadata factual; platform traces are not generated by this Skill.

## Extract before drawing

Read [references/graph-format.md](references/graph-format.md). Build `route.json` from the original material. Assign stable IDs to each source, node and connection. Every node and edge needs an evidence item with source ID, exact short quote and a precise locator. Record source file hashes. For PDF inputs, retain the original PDF and create a page-numbered text extraction in the work directory. Cite original page and paragraph, not only extraction offsets. OCR uncertainties remain explicit.

For every edge, answer: which named endpoint is the source, which is the destination, what is conveyed, and which original sentence establishes the direction? Use `sequence` for procedural order, `material` for explicit material transfer, `information` for a measured signal or record, and `energy` only when stated. A return is a routing pattern, not a scientific substance. Put its condition on the edge. Never invent thresholds or instruments. Separate repeated component instances using IDs even if their labels match.

Draw unresolved connections only if the task asks, and visibly mark them unresolved. Otherwise omit them with a specific uncertainty record. Use the requested entity count as an audit target, not as permission to add nodes. Source quotation checks prove traceability, not scientific correctness. Review each interpretation against the passage in context.

## Lay out and export

Use a dominant reading direction and short orthogonal connectors. Put decision diamonds at actual branches, detection nodes where a reading is made, and return loops outside the main route. Use shape and line style as well as color. Keep the graph a scientific schematic; avoid decorative icons, shadows and unrelated cards. Do not encode quantity through size or color unless the input defines that mapping. State "schematic, not to scale" when spatial proportions are unspecified.

Set node boxes and edge ports explicitly. Place edge labels beside the correct segment, never over a node. Use explicit `via` points for branches and returns. Adjust the canvas or split complex routes into linked panels rather than shrinking labels into illegibility. The bundled renderer is intentionally small and does not perform automatic graph layout or scientific extraction.

Run with Python 3.10+ and PyMuPDF already supplied by the environment:

```sh
python /skills/weekly-skill/scripts/route.py render /app/work/route.json --out /app/output/route --dpi 200
```

It writes editable `.svg`, vector `.pdf`, `.png` rendered from that PDF, `.semantic.json` and `.checks.json`. SVG text remains text; source IDs appear in SVG groups and metadata. Arrowheads are explicit polygons because some SVG renderers drop marker-based arrows. Read the checks and actually open the PNG. Check every arrowhead, endpoint, condition, node label, legend and canvas edge. Inspect PDF text for missing glyphs, font substitutions and line breaks. Record inspection evidence and fix what you can. Structural checks are not a visual pass.

If PyMuPDF is absent, inspect the declared tools and use an available SVG renderer such as Inkscape or LibreOffice without silently installing software. Preserve the SVG and report a partial result if real exports cannot be produced. If supplied SVG uses filters, external assets or markers, compare exports against the source render before claiming fidelity.

## Preserve sources during an edit

For a diagram created by this script, retain the old graph and original outputs. Apply a narrow patch to stable IDs with a quoted edit request:

```sh
python /skills/weekly-skill/scripts/route.py edit /app/work/route.json /app/work/patch.json --out /app/work/route-v2.json
python /skills/weekly-skill/scripts/route.py render /app/work/route-v2.json --out /app/output/route-v2
```

The patch records before/after values and parent graph SHA256. Existing scientific evidence is retained. Presentation changes can adjust labels and geometry. A scientific label correction still needs a source that supports it; an edit request alone is not scientific evidence. To change topology, create a new graph version with explicit source-backed added/removed relations and a change record. Do not disguise topology changes as presentation edits.

For a supplied editable SVG or other native diagram, keep it as the editing base. Do not redraw it through the bundled graph model. Patch the specific named XML elements or native objects, preserving unaffected IDs, text, styles, transforms, definitions and source references. Save original and revised files. Compare canonical XML of untouched subtrees, or native object properties when applicable. For text replacement in SVG `<tspan>`, preserve line wrapping or recompute only the requested text box. Record original SHA256, changed IDs, before/after values, request source and any unavoidable changes. If the source is raster-only, label the reconstruction and its uncertainty; do not claim source-preserving native editing.

## Deliver and verify

Return the actual editable source, semantic mapping, requested exports, change log and sources. Include original and revision when requested. Fill every actual `output_contract` field and `case_id` in `result.json`. Add status, missing inputs, uncertainty, artifact paths, export properties, source hashes and human confirmation state if the case permits extra fields. Never say "human approved" without an actual approval.

Verify node and connection counts against the source, compare every displayed label with the mapping, follow every directed path including branches and return loops, check the destination port and arrow tip, and confirm source links survived edits. Record remaining limitations concretely. Do not claim quality gains or official-case success from a local example.
